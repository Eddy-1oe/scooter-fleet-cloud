Feature plan for the scooter fleet management dashboard, organized into six modules across three build phases.

Already built Build next Build later (after LoRa)
Phase 1 — Core operations
Live telemetry dashboard
What you have now
Per-scooter telemetry cards
Speed, battery, voltage, mode, brake, light
Fleet summary metrics
Online count, avg battery, locked count
Remote controls per scooter
Lock, unlock, mode, light, walk, power
Broadcast commands
Lock ALL / Unlock ALL with one button
Sort & filter scooters
By battery level, status, mode, or ID
Alerts & notifications
Know before problems escalate
Low battery warning
Flag scooters below 20% on the dashboard
Offline alert
Visual indicator when a scooter drops off WiFi
Alert log panel
Running list of events — went offline, low battery, locked
Push / SMS alerts
Notify manager phone when critical event occurs
Phase 2 — Fleet intelligence
History & analytics
Understand usage patterns
Ride session logging
Server saves each trip — start time, duration, distance
Battery discharge tracking
Graph battery % over time per scooter
Usage heatmap
Which hours of day each scooter is most active
Per-scooter health score
Flag scooters with abnormal voltage or speed readings
Fleet & user management
Register and control access
Scooter registry
Assign names, notes, and status tags (active, charging, maintenance)
Maintenance mode
Mark a scooter as out-of-service, hide from rider app
Speed limit per scooter
Lock a scooter to ECO or D mode remotely
Rider accounts
Login, assign scooter to rider, end session remotely
Phase 3 — After LoRa upgrade
Live map & tracking
Requires GPS on each scooter
Live map view
All scooters shown as dots on a campus/town map
Geofence zones
Auto-lock when scooter leaves allowed area
Trip route replay
Replay a trip on map from GPS trail data
Find nearest scooter
Rider-facing feature — show closest available unit
Rider-facing app
Separate from management console
Scan-to-ride QR unlock
Rider scans QR on scooter, sends unlock command
Rider speed & battery view
Simple read-only telemetry for the person riding
End-of-ride reporting
Rider confirms return, triggers re-lock
Trip history for rider
Distance, duration, battery used per trip
